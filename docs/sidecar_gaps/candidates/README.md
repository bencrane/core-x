# candidates/ — the /sidecar-priority dossier layer

One living dossier per standalone sidecar-growth idea, reconciled across ALL gap reports
(top-level raw + parked-structural inside `processed/` dispositions). `PLATE.md` is the
canonical ranked 1-pager, regenerated wholesale each `/sidecar-priority` run.

Dossier schema: (a) capability stated once, canonically; (b) evidence trail — dated links to
every raw entry touching it; (c) proposed shape + projected artifact delta; (d) adjacency
candidates; (e) status: `open` / `parked`(+why) / `promoted`(+build stamp) / `routing-fix`.

Lifecycle: `/sidecar-priority` births/updates dossiers and regenerates PLATE.md (read-only
toward raw reports). `/sidecar-gaps` Mode 2 consults dossiers at gating and flips statuses in
its disposition PR. `/sidecar-build` executes. Raw reports are never edited here.
